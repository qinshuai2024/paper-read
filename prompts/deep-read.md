# Stage 1+2 — DEEP READ (全局导览 + 逐章精读, 单文件输出)

## 目标

把 **全局导览 (扩展引言)** 与 **逐章精读** 合并到**同一个文件** `<paper_dir>/deep-read.md`，按二级标题分隔，便于滚动浏览与统一维护。

文件结构：

```markdown
# Deep Read: <Paper Title>

## §0 扩展引言 (全局导览)             ← Stage 1
   ...

## §1 Introduction / <中文标题>       ← Stage 2 第 1 章
   ...

## §2 Related Work / <中文标题>       ← 第 2 章
   ...

## §3 ...
```

每章生成完毕后**追加**到同一文件末尾。**不再为每章建独立文件**。

## 路径约定

本文件中所有 `<paper_dir>` 一律解析为 **SKILL.md Step 0 已创建的论文目录绝对路径**:

```
<paper_dir> = <OUTPUT_BASE>/papers/<dated-slug>/
```

写盘时必须用 SKILL.md Step 0 计算好的绝对路径替换占位符, 不要把字面字符串 `<paper_dir>` 写进命令。

## 输入

- `<paper_dir>/sections.json`
- `<paper_dir>/ReadingPlan.md`
- 已生成的 `deep-read.md`（追加用）
- `<paper_dir>/qa-log.md` 中累积的问答与未解疑点

## ────────────────────────────────────────
## Phase A — § 0 扩展引言 (Stage 1)
## ────────────────────────────────────────

### A.1 抓取与切分回填

按以下顺序提取材料：

| 引言段落 | 主要来源 | 回填来源 |
|---------|---------|---------|
| ① 大背景 / 重要性 | Intro §1 第 1-2 段 | Related Work 首段, Conclusion 第 1 句 |
| ② 现有工作痛点 / Gap | Intro 中段 ("However...") | Related Work 全文, §3 Motivation |
| ③ 本文动机 + 核心 idea | Intro "In this paper we..." | Abstract, §3 / §4 关键定义, 框架图 caption |
| ④ 方法概述 | Intro 方法段 | §4 / §5 方法章节首段, 主要框架图 caption |
| ⑤ 实验设置与主要结果 | Intro 结果段 | §6 实验首段, 主表 caption（**不引用具体数字**） |
| ⑥ 贡献清单 | Intro 末尾 contributions | 重新表述, 与 ③④ 一致 |
| ⑦ 结论与限制 | Conclusion | Limitations 章节（若有） |

### A.2 写入扩展引言

把内容写入 `<paper_dir>/deep-read.md`，结构如下（**这是整个文件的第一节**）：

```markdown
# Deep Read: <Paper Title>

> 本文档由 paper-read skill 生成。包含 § 0 扩展引言 (全局导览)
> 和 § 1+ 逐章精读。所有论点末尾用 [源自 §X] 标注来源章节。

---

## §0 扩展引言 (全局导览)

### ① 这件事为什么重要 (大背景)
<2-4 段>
[源自 §1.1, Related Work 首段]

### ② 现有工作走到了哪里, 又卡在哪里 (现状与 Gap)
<2-4 段, gap 用粗体: **Gap: ...**>
[源自 §1.2, §2 Related Work, §3 Motivation]

### ③ 本文的核心 idea 与洞察 (动机)
<2-4 段>

**核心洞察**: ...

[源自 §1.3, Abstract, §3]

### ④ 方法概览 (不展开公式)
<2-3 段, 框架级>
[源自 §4 / Fig.1 / Algorithm 1]

### ⑤ 实验主要在做什么 (粗粒度)
<1-2 段, 不引用具体数字>
[源自 §6 首段, Tab.1 caption]

### ⑥ 贡献清单 (作者声称的)
1. ...
2. ...
3. ...
[源自 §1.4 / 末尾 contributions]

### ⑦ 结论与局限
<1-2 段; 如作者未承认 limitations 标注 🚩>
[源自 §7 Conclusion, §X Limitations]

### 全局阅读地图
| 章节 | 主要任务 | 重要性 | 后续是否精读 |
|------|---------|-------|------------|
| §1 Introduction | 已扩写覆盖 | ⭐⭐⭐ | 可略 |
| §2 ... | ... | ⭐⭐ | 按需 |

### 🚩 Stage 1 已经看出的疑点 (如有)
- ...

---
```

### A.3 风格规则

- **完整中文输出**, 专业术语首次出现给中英对照（例如"自注意力 (self-attention)"）。
- 比原引言**长 3-5×**。详尽度由 ReadingPlan 决定。
- **不展开公式**, **不引用具体数字**, 留给逐章。
- **每个论点末尾标 `[源自 §X]`**。
- **资深口吻**: 先讲故事 → 再讲机制 → 最后点贡献。

### A.4 写盘后回显与暂停

按 SKILL.md "终端回显规则", **不要在终端重复打印 § 0 全部内容**。只回显:

```
== § 0 扩展引言完成 ==
文件: papers/<dated-slug>/deep-read.md (新增约 <N> 字)
骨架: ① 背景 → ② Gap → ③ 核心洞察 → ④ 方法概览 → ⑤ 实验 → ⑥ 贡献 → ⑦ 结论
核心洞察一句话: <30 字内>
🚩 已看出的疑点: <若有, 一句话; 无则省略此行>
👉 完整查看: cat papers/<dated-slug>/deep-read.md

现在你可以:
  · 问任何全局性问题
  · 让我重写某一段 (例如 "③ 写得太抽象, 举个具体例子")
  · 说 "show §0" 直接在终端打印完整内容
  · 直接说 "开始精读" / "下一章" / "next" 进入第 1 章

我会等你。
```

```bash
  cat > "<paper_dir>/qa-log.md" <<'EOF'

> 三段结构: Part 1 全程问答 (按时间) / Part 2 未解疑点 / Part 3 声明-证据表
> 由 paper-read skill (Stage 1+2+3) 持续追加。

## Part 1 — 全程问答 (按时间)

<!-- 新条目按时间追加在此 -->

---

## Part 2 — 未解疑点 (Open Questions)

<!-- 各章遗留疑点追加在此 -->

---

## Part 3 — 声明-证据表 (Claim-Evidence Map)

<!-- 各章核心声明追加在此 -->
EOF
fi
```

之后用户的每个问题, 把 Q&A **追加**到 Part 1 段:

```markdown
### [§0 全局] Q<n>: <一句话问题摘要>
**时间**: 2026-06-07 13:21 (北京时间)
**Q**: <用户原问>
**A**: <Claude 答。本文内论点末尾标 [源自 §X]; 涉及外部引用的内容按下方"外部查证"标注 [据检索:...] / [本文转述:§X] / ⚠️[未能查证]>
**标签**: #stage1 #motivation
```

> **时间必须取真实当前时间** (写盘前 `TZ=Asia/Shanghai date "+%Y-%m-%d %H:%M"`), 不要凭印象推断。格式 `YYYY-MM-DD HH:MM (北京时间)`, **不进标题**。详见 SKILL.md "qa-log Part 1 写入模板"。

#### 外部查证 (防幻觉, 回答前先判定)

用户的提问是否涉及**当前 PDF 正文之外**的事实? —— 典型: "§2 提到的 <某工作> 具体怎么做的""这篇相关工作和本文区别在哪""<某方法> 是谁提出的""这个领域背景是什么"。

- **涉及外部事实** → **先实际检索再答**, 禁止纯凭训练记忆。仅使用当前环境已安装 / 已配置的工具；不可用时跳到下一项，全部不可用时标注未能查证。准确度优先回退链 (详见 SKILL.md "精读中查证外部引用的工具链"):
  1. `/semantic-scholar "<被引论文标题>"` (首选: 论文实体 + TLDR + venue + 引用数)
  2. 若是预印本 → `/arxiv "<标题或 arXiv ID>"` (可下 PDF 读原文, 最准)
  3. S2/arXiv 无果 → `/openalex "<标题>"` (覆盖最全兜底)
  4. 学术库全无 → `mcp__exa-key__web_search_exa` (加 `category:"research paper"`) → 仍不行 `WebSearch` (网页兜底)
- **只问本文内容** (方法/公式/实验本身) → 直接答, `[源自 §X]` 即可, 不必联网。

**回答时三态标注, 诚实分档**:

| 标注 | 何时用 |
|------|--------|
| `[据检索: <标题 / arXiv ID / URL>]` | 已实际查证, 给可核对来源 |
| `[本文转述: §X]` | 只复述了本文作者对该工作的描述 (未独立核原文, 可能带作者偏见) |
| `⚠️[未能查证]` | 没搜到/不可靠: 明说"这是我的印象, 未经核实, 建议自查", 绝不伪装成事实 |

> **不滥查**: 常识背景或本文已说清的不必联网。但凡是"被引工作/外部方法**具体做了什么**", 默认偏向先查再答。查到的来源 (标题/ID/URL) 必须落进 `**A**:`, 保证有迹可循。

如果用户问到本文某具体章节细节 (将在后续精读展开), 告诉用户 "这个细节我们在精读 §X 时会展开"，把问题追加到 `qa-log.md` 的"未解疑点"段（详见 Phase B.6）。

仅当用户明确说 "开始精读 / 下一章 / next" 才进入 Phase B。

### B.1 确定下一章与翻译策略

读 sections.json 章节列表 + `ReadingPlan.md` 的"全局阅读地图"表。

**关键**: 每章动笔前必须先读出 ReadingPlan 对该章的 `翻译策略`, 按下表执行:

| 策略 | 翻译做法 | 章末解读 | 反问 |
|------|---------|---------|------|
| `SKIP` | 不写翻译段, 章末仅 2 句中文小结 + **原文索引** (页码 + 字数 + sections.json idx, 见下方 SKIP 模板) | 跳过"资深解读"全部小节 | 跳过反问 |
| `DIGEST` | 写 4-6 句中文摘要式段落 (合并整章) | 写"2.1 真正重要的 1-3 句话"即可, 其余跳过 | 1 题理解检查即可 |
| `STANDARD` (默认) | 关键段中译 + 其余意译; 公式逐行 + 直觉; 图表 caption 中译 + "想告诉你什么" | 写 2.1 + 2.2 + 2.4 (跳过 2.3 / 2.5 除非有特殊价值) | 按 ReadingPlan 批判强度: 高=5 / 中=3 / 低=2 |
| `FULL` | 完整逐段中译 + 术语首次对照 + 公式逐行 + 推导提示 (若 ReadingPlan 公式推导=必须) + 图表 caption 中译 + "想告诉你什么" + 容易看漏的细节 | 写 2.1-2.5 全部小节 | 同上, 高/中/低 题数 |

> **进度感知 (progress.json)**: 每次写完 §0 / 每章 / Q&A, 都必须**同回合**更新 `<paper_dir>/progress.json` 的 `sections_done` / `next_action` / `last_updated`。下次启动时 (新会话 / 隔几天回来), SKILL.md Step 0 的"幂等检查"会**优先读 progress.json** (没有才 fallback 扫 deep-read.md 末尾的 `## §X`), 显示断点摘要 + 三选项: 继续 §<X+1> / 重读 §X / 跳到 Stage 3。详见 SKILL.md "progress.json 断点续读元数据" 节。

> **Related Work / DIGEST 章被追问时**: DIGEST 只做摘要式概括, 本就不展开各条被引工作的细节。一旦用户**追问** "刚才那条 <某工作> 具体做了什么 / 和本文比怎样", **不要**把 DIGEST 摘要硬撑成详细解释 (那等于凭记忆编), 而是触发上方 "外部查证" 流程: `/semantic-scholar` → `/arxiv` → `/openalex` → exa, 查到再答并标 `[据检索:...]`。这正是 DIGEST 省下来的成本该花的地方。

#### SKIP 章节模板 (防断引)

若 ReadingPlan 标某章为 SKIP, 也要写入 deep-read.md 一个**极短**的 §X 段, 必须包含原文索引以便用户回查:

```markdown
## §X. <Original Section Title> / <中文标题>  [SKIP]

> **章节定位**: <一句话: 这章是文献综述 / 理论铺垫 / ...>
> **跳过理由**: <已被 §0 扩展引言覆盖 / 用户配置为 SKIP / ...>

### 章末小结 (2 句)
1. <一句话核心要点>
2. <一句话与本文关系>

### 📌 原文索引 (回查用)
- sections.json idx: `<N>` (字段 `sections[N].text`)
- 原文字数: ~<C> 字
- 关键 keyword (Ctrl+F): "<英文关键词 1>", "<英文关键词 2>"
- 完整原文:
  - **HTML 源** (`backend: arxiv-html`, `page` 为 null): 见 arXiv HTML `https://arxiv.org/html/<id>` 对应章节, 或本地 `source.html`
  - **PDF 源** (`backend: pymupdf/pdftotext`): 见 `source.pdf` 第 <P_start>-<P_end> 页 (页码取自 `sections[N].page`)
```

> **页码可能为 null**: HTML 源的 sections.json 没有页码 (`page: null`, `n_pages: null`)。此时原文索引省略页码行, 改用 sections.json idx + keyword 定位; 不要凭空编造页码。

写完此段**自动推进到下一章**, 不停顿三选项。仅在 `STANDARD/FULL/DIGEST` 章才触发三选项暂停。

### B.3 三选项暂停 (按全局回显规则)

**不要在终端打印 §X 全部内容** (它已在 deep-read.md 里)。每章结束后, **永远**输出回显模板:

```
== §X <章节英文标题> 精读完成 ==
文件: deep-read.md (新增约 <N> 字, 翻译策略: <FULL/STANDARD/DIGEST/SKIP>)
本章骨架:
  · §X.1 <小节> · §X.2 <小节> ...
  · 关键公式: <若有, 仅给编号 + 1 句直觉; 无则省略此行>
  · 关键图: <Fig.X — 一句话; 无则省略此行>
核心声明 C-X.1 (强度: 强/中/弱): <≤ 30 字>
反问已生成: Q1 理解 / Q2 假设 / ... (按 ReadingPlan 批判强度)
👉 完整查看: cat papers/<dated-slug>/deep-read.md
👉 直接看反问: 说 "show questions"

接下来:
  [1] 继续 → 进入 §<X+1>
  [2] 提问 → 关于本章任何问题
  [3] 跳过 → 跳过 §<X+1> 直接到 §<X+2>

也可以说: "重读 §X" / "show §X" (终端展开) / "进入 Stage 3"
也可以说: "连读到 §<Y>" / "一口气读完 DIGEST 章" / "全部连读" (批量模式, 见 B.3.bonus)
```

**默认: 不自动连读下一章** (除非该章是 SKIP 策略)。

#### B.3.bonus 批量连读模式 (Batch Mode)

资深读者在自己熟悉的领域不需要每章停下。当用户主动说出以下指令之一, 进入批量模式:

| 用户指令 | 行为 |
|---------|------|
| `连读到 §<Y>` | 从当前章一直读到 §Y (含), 中间不暂停; §Y 完成后才出三选项回显 |
| `一口气读完 DIGEST 章` | 自动连读所有翻译策略=DIGEST 的章节, 直到下一个 STANDARD/FULL 章前停下 |
| `全部连读` | 直接读到末章, 中间不暂停; 末章完成后给 Stage 2 总览回显 |

**批量模式期间的简化回显** (每章只回显 1 行, 不打三选项模板):

```
[batch] §X <英文标题> ✓ (策略: <STR>, 新增 <N> 字, 核心声明 C-X.1: <≤20 字>)
```

最后一章完成时回归完整模板 (含三选项, 让用户回到交互节奏)。

**批量模式中止条件 (强制停下)**:
1. 任何一章的反问暴露关键误解 (`#critical-question` 标签)
2. 任何一章 ReadingPlan 标 `FULL` 且批判强度=高 (这种章值得停下讨论)
3. 用户在批量过程中说"停" / "暂停" / "我有问题"

中止后回到普通三选项模式。

### B.4 反问反馈循环

用户答了 Q-N：
1. 反馈：哪部分对、哪部分没说出来、参考答案。
2. 把这次问答**追加**到 `qa-log.md`, 标 `#critical-question` 如果暴露关键误解。
3. **暴露关键误解时不允许进入下一章**, 先用 1-2 段重新讲清楚。

### B.5 维护 qa-log.md (三段合一文件)

> ⚠️ **关键规则: qa-log 完整内容写盘, 终端只给短摘要** (详见 SKILL.md "qa-log.md 写盘约定")
>
> 与 deep-read / reading-notes 同规则: **写盘即少回显**。
>
> - ❌ 禁止把完整解释 (含表格 / 伪代码 / ASCII 图) 在终端打一遍, 然后又写进 qa-log (重复占 token)
> - ❌ 禁止只在终端打长版, qa-log 只留要点 (终端日志会消失, 档案残缺)
> - ❌ 禁止 qa-log 只写一句结论, 推理过程靠用户回翻对话
> - ✅ Claude 内部生成完整解释 → 直接写进 qa-log Part 1 (含表格/伪代码/ASCII 图/推导链)
> - ✅ 终端只回 3-6 行短摘要: 一句话结论 + 2-4 个关键 bullet + `👉 完整解释: cat papers/<dated-slug>/qa-log.md`
> - ✅ 用户说 "show qa Q3" 时, 才把对应 Q&A 完整输出到对话
> - ✅ 用户挑出歧义后的修订版表述, 修订版并入 qa-log 对应条目, 终端回"已修订, 见 Q<n>.A.<x>"
>
> 终端摘要模板:
>
> ```
> == Q<n> 已答 + 写入 qa-log ==
> 一句话结论: <≤30 字>
> 关键要点:
>   · <bullet 1, ≤20 字>
>   · <bullet 2, ≤20 字>
> 👉 完整解释 (含表格/推导): cat papers/<dated-slug>/qa-log.md
> ```
>
> 理由: 用户当下可问"详细打印 Q<n>"按需展开; 长期靠文件; 终端是导航不是档案。

`qa-log.md` 是**单一文件三段结构**：

```markdown
# QA Log: <Paper Title>

## Part 1 — 全程问答 (按时间)

**时间**: 2026-06-07 13:21 (北京时间)
**Q**: ...
**A**: ...
**标签**: #stage1

### [§1] Q2: ...
**时间**: 2026-06-07 14:05 (北京时间)

## Part 2 — 未解疑点 (Open Questions)

- [ ] Q-0.1: ... — 计划在 §X 解决 / 留给 Stage 3

### §X 留下
- [ ] Q-X.1: ...

---

## Part 3 — 声明-证据表 (Claim-Evidence Map)

### §X 的声明
| ID | 声明 | 证据位置 | 类型 | 强度 | 备注 |
|----|------|---------|------|------|------|
```

每章结束时把当章新增的声明、未解问题分别追加到 Part 2 / Part 3 对应位置。

### B.6 论文读完时

所有非"跳过"章节完成后, 输出：

```
== Stage 2 全部章节完成 ==

deep-read.md 已涵盖: § 0 扩展引言 + §1 .. §N 全部精读
跳过: <list>
qa-log.md 累计:
  - 问答: M 条
  - 未解疑点: K 条
  - 章末声明: L 条

进入 Stage 3 合卷? (yes / 我还想重读 §X / 我想停在这里)
```

## 关键规则

- **写盘即少回显**: § 0 / 每章 / qa-log 都按 SKILL.md "终端回显规则"输出短预览, 不复制全文。
- **章节级翻译**: 每章动笔前先读 ReadingPlan 的"全局阅读地图"中该章的策略 (SKIP/DIGEST/STANDARD/FULL), 按表执行, 不一刀切。
- **单文件输出**: 整个 Stage 1+2 只写 `deep-read.md` 一个文件, 不创建 `chapters/` 子目录。
- **章节顺序由 sections.json 决定**, 不擅自调换。
- **公式翻译看策略**: STANDARD/FULL 才公式逐行 + 直觉; DIGEST 仅核心公式 + 直觉; SKIP 跳过。即使展开, "推导步骤"仅在 ReadingPlan 公式推导=必须 时才写。
- **公式书写: 文档用 LaTeX, 终端用纯文本**: 写进 `deep-read.md` / `qa-log.md` 的公式一律用 LaTeX (`$...$` 行内 / `$$...$$` 独立, 渲染后正常显示); 终端回显 (章末骨架、Q&A 短摘要、三选项) **绝不打裸 LaTeX**, 改用 Unicode/ASCII 纯文本 (如 `∑_a π(a|s_i) log[π_i/π_j]`)。终端无法渲染 LaTeX, 打 `\frac`/`\sum` 只会显示反斜杠。详见 SKILL.md "终端回显规则 → 公式书写规则"。
- **图表翻译看策略**: STANDARD/FULL 才中译 caption + "想告诉你什么"; DIGEST 仅 caption 中译; SKIP 跳过。
- **反问数量看强度**: 高=5 / 中=3 / 低=1-2; SKIP/DIGEST 章默认仅 1 题或不出。每题独立, 不打包成长段。
- **暴露不懂时不前进**: 宁可在一章停留, 也不让误解累积。
- **不替作者圆场**: 跳跃推导、缺失假设、与前文矛盾 → 解读部分必须明确指出。
- **外部引用必查证, 禁止凭记忆瞎编**: 凡涉及当前 PDF 之外的事实 (被引论文/相关工作具体做了什么、方法出处、领域背景), 必须先检索 (`/semantic-scholar` → `/arxiv` → `/openalex` → exa) 再答, 并按三态标注 `[据检索:...]` / `[本文转述:§X]` / `⚠️[未能查证]`。详见上方 "外部查证" 小节与 SKILL.md "关键规则"。
- **三选项暂停默认不省略** (SKIP 章除外, 自动推进), 即使用户连续说"继续"也要每章重新打出回显模板。**唯一例外**: 用户主动进入批量连读模式 (B.3.bonus), 此时按简化回显执行, 但末章 / 暴露关键误解 / 用户喊停时立即恢复完整模板。
- **show / 终端打印 兜底**: 用户说 "show §X" 时把对应章节内容完整输出到对话 (此时才允许长输出)。
